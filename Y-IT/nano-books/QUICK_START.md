## What Is This Project?

The Y-IT Nano-Books series transforms comprehensive business analysis into compact, multi-format reality checks designed to prevent financial disasters. Each "nano-book" covers one hyped business opportunity (dropshipping, POD, affiliate marketing, etc.) with brutal statistical honesty.

## Quick Start: Different Roles

### I'm A Writer

**Start here:**
1. Open `/print/MANUSCRIPT_TEMPLATE.md`
2. Choose your topic (dropshipping, POD, etc.)
3. Research statistics (failure rates, average losses, timelines)
4. Follow the template section-by-section
5. Target: 4,000 words across 6 sections

**Key documents:**
- `MANUSCRIPT_TEMPLATE.md` - Your writing guide (everything you need)
- `STRATEGIC_ANALYSIS.md` - Content distribution strategy (what goes in print vs web)
- `config.json` - Word count targets per section

**Pro tips:**
- Keep tone satirical but empathetic ("beautiful, stubborn fool")
- Every statistic needs a source
- Use REAL guru quotes (screenshot them)
- Case studies should feel like real people (anonymized composites)

### I'm A Designer

**Start here:**
1. Open `/docs/IMAGE_SPECS.md`
2. Review the 6 required images per nano-book
3. Download brand assets (if available)
4. Start with title page hero illustration

**Image requirements:**
- Cover (exterior, typography-forward + small icon)
- Title page hero (split-frame: promise vs reality)
- 3 case study icons (simplified archetypal representations)
- Cost breakdown ASCII table (text-based)
- Decision flowchart (text-based)

**Key documents:**
- `IMAGE_SPECS.md` - Complete visual specifications
- `config.json` - Exact dimensions and formats

**Pro tips:**
- 300 DPI minimum, CMYK color mode
- High contrast (must print clearly at 6×9" size)
- Limited color palette (2-3 colors max)
- Web version can be more complex/animated

### I'm A Developer

**Start here:**
1. Review `/config.json` for tech stack
2. Check `/web/` directory structure
3. Plan interactive features (calculators, expandable sections)

**Core features to build:**
- Interactive cost calculator (user inputs their numbers)
- Expandable content sections (click to reveal deep-dives)
- Progress tracking (which sections user has read)
- QR code analytics (track print-to-web conversions)
- AI Evaluator integration (product/idea analysis)

**Key documents:**
- `config.json` - Technology stack, feature list
- `STRATEGIC_ANALYSIS.md` - Multi-format content distribution map

**Pro tips:**
- Print QR codes link to SPECIFIC sections (not just homepage)
- Web version should feel premium (justify $7.99 upgrade)
- Mobile-first (people scan QR codes on phones)

### I'm A Podcast Producer

**Start here:**
1. Review `/podcast/` directory structure
2. Read `STRATEGIC_ANALYSIS.md` section on podcast format
3. Plan episode structure (20-25 min per topic)

**Episode format:**
- Segment 1: Real entrepreneur interview (failed in this space)
- Segment 2: "Guru Roast" (dissect actual guru pitch)
- Segment 3: "Calculator Corner" (walk through math)
- Closing: Cross-sell books, free AI evaluator CTA

**Key documents:**
- `STRATEGIC_ANALYSIS.md` - Podcast content strategy
- Print manuscripts - Source material (but extend beyond, don't just read)

**Pro tips:**
- NOT an audiobook (must add unique value beyond written content)
- Find real interview guests (Reddit, Twitter, Indie Hackers)
- Record actual guru pitches (YouTube, webinars) for dissection

## Key Strategic Decisions (Already Made)

### ✅ Format: 6×9" Trade Paperback
**Why:** Better margins, more portable, credible, forces brutal editing

**NOT 8.5×11"** (would feel empty at 12-14 pages, higher print costs)

### ✅ Page Count: 12-14 Pages
**Why:** Complete standalone experience, low barrier to purchase, forces prioritization

**NOT 35+ pages** (dilutes impact, increases cost, reduces shareability)

### ✅ Case Studies: 3 Detailed (Print) + 4 Summarized
**Why:** Print gets Trust Fund Failure, Spiritual/Wellness, Pyrrhic Victory; Web gets all 7 full

**NOT all 7 in print** (would consume 14+ pages alone)

### ✅ Title Page: Single Hero Image + QR
**Why:** Space efficiency, immediate impact, demonstrates print-to-web value gap

**NOT comic strip in print** (too space-intensive, save for web version)

### ✅ Data Viz: ASCII Text-Based
**Why:** Faster to produce, more credible (looks like real spreadsheet), easier to update

**NOT complex infographics** (expensive, slow to produce, dates quickly)

## Common Questions

### Q: Can I change the word count targets?

**A:** Stay within ±10% (3,600-4,400 words total). Going significantly over breaks page count budget. Going significantly under makes print feel incomplete.

### Q: What if I find statistics that contradict the "it will fail" narrative?

**A:** Include them honestly. Y-IT brand = statistical honesty, not cherry-picking. If 30% succeed (not 8%), say so. Then explain why that's still terrible odds for most people.

### Q: Can I add more images?

**A:** Only if you cut text proportionally. 6 images = budget for 12-14 pages. More images = fewer pages for text = incomplete content.

### Q: Should the podcast just read the book aloud?

**A:** NO. Podcast must extend beyond written content (interviews, guru dissection, listener calculations). If it's just an audiobook, no one upgrades to web version.

### Q: What if the business model is actually viable for some people?

**A:** Acknowledge it! Section 4.1 covers "When It MIGHT Work." But be clear about prerequisites (capital, time, expertise, luck). If 20% succeed, that means 80% fail - still worth a warning.

## The Core Philosophy

**"Brutal honesty delivered efficiently."**

Every decision in this project serves one goal: **Prevent financial disasters by delivering statistical reality in the most compelling, accessible, multi-format package possible.**

If a choice doesn't serve that goal, cut it.

- 6×9" format? Forces ruthless editing (serves goal ✓)
- Comic strip in print? Wastes 2 pages (doesn't serve goal ✗)
- ASCII tables? Fast, credible, clear (serves goal ✓)
- Complex infographics? Slow, expensive, dates quickly (doesn't serve goal ✗)

**The constraint is the feature.** Limited pages = maximum impact per word.
